### 两个沙箱坑（不解决会白折腾）

1. **长驻服务活不过单次工具调用**：`nohup ... &` / `disown` 起的 vite 会打印
   `VITE_READY` 然后在本次 Bash 调用结束后被杀；下一调用 curl 必然 connection refused。
   → **必须把「起服务 + 驱动浏览器 + 断言」放进同一次调用/同一个进程**（smoke 脚本内部
   spawn vite 就是这个原因）。
2. **localhost 探测必须 `curl --noproxy '*'`**：环境里有 `HTTP_PROXY=127.0.0.1:61804`，
   不加会得到 502/000 的假失败。
3. vite 首次启动会因 `safe-delete` 拒绝清 `frontend/node_modules/.vite/deps`（>50 文件）而失败；
   缓存已热后正常。要绕过可把 `cacheDir` 指到 `/tmp`（用 `createServer` 编程式启动）。
4. **给人看的常驻预览要用托管后台任务，不是 `nohup`**。Bash 工具的 `run_in_background: true`
   起的 vite 能跨调用存活（上面的 1 说的是 `nohup &`，二者机制不同）。
   启动命令（把 stdout 落盘以便读端口）：
   ```bash
   cd frontend && node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5199 --strictPort > /tmp/vite-mock.log 2>&1
   ```
5. **`--host 127.0.0.1` 不能省**。不指定时 Vite v8 只监听 IPv6 `[::1]:5199`
   （`lsof -nP -iTCP:5199 -sTCP:LISTEN` 显示 `TCP [::1]:5199`），于是
   `http://127.0.0.1:5199` 直接 exit 7 / HTTP 000，而 `localhost` 与 `[::1]` 正常 200。
   内置浏览器预览面板走 IPv4 回环，探测失败会**回退去服务磁盘上的原始 HTML**（对 `mock.html`
   意味着没有 Vite 转换 → 白屏）。显式绑 `127.0.0.1` 后两种写法都通。
6. 端口固定为 **5199**（`--strictPort`），mock 入口是 `/mock.html`。

### e2e 断言口径的一条硬教训

**mock 的 PTY 不模拟 tty 回显**（只有批量发送路径会显式回显）。因此「往终端打字再看
回显」的断言必然假失败。派发类断言要挑**无内容依赖**的可观测量——本轮用的是「终端搜索
面板」：把 `search` 从平台默认键位改到新组合后，旧默认键位不再打开面板、新组合能打开、
`Esc` 能关闭。这同时证明了「注册表被真实派发链路消费」，而不是只写进了 localStorage。

## 第三轮：i18n 键引用护栏 + `d983f8fc` 回归修复（同分支）

### 为什么加护栏

`workbenchMessage` 查不到键时**原样返回 key**（`i18n.ts` 最后一行 `?? key`）。而既有断言
`workbench.spec.ts:171` 只比对**七语之间**键集合是否一致——**七语同时缺失的键它天然抓不到**。
上一轮我刚退役了两个键，于是补护栏来验证退役是否干净，结果直接抓出 19 个既有缺陷。

### 新增护栏：`frontend/src/lib/i18nKeyReferences.spec.ts`（5 个断言）

- 用 `import.meta.glob("../**/*.{vue,ts}", { query: "?raw", eager: true })` 内联源码，
  不需要 `node:fs`，默认 node 环境即可跑（仓库此前只有 `../App.vue?raw` 这种单文件用法）。
- 扫描两类引用：`t("a.b")` / `props.t(...)` / `translate(...)` / `workbenchMessage(...)`，
  以及 `labelKey: "a.b"`。实测 903 + 19 处、617 条唯一引用、覆盖 130 个源文件。
- 断言：①扫描面非空**且分类型下限** ②全部可解析 ③任意语言都不把键名当文案返回
  ④退役键不得复活 ⑤新命名空间必须被扫到。

### 两个「护栏自己出错」的教训（重要，写测试时复用）

1. **多正则统一取 `match[2]` 是错的**。属性式 `/prop\s*:\s*(["'])([^"']+)\2/` 的第 2 组是
   **引号字符**，键在第 3 组。当初统一取 `match[2]` 导致 19 处 `labelKey` 被静默跳过，
   而总数看起来依旧健康。→ 每个 pattern 显式携带 `keyGroup`，并且**必须给每一类加下限断言**，
   否则某一类归零不会被发现。
2. **`*Key` 通配形状太宽**。会命中 `shiftKey`/`ctrlKey`/`altKey`/`metaKey`（DOM 修饰键）、
   `purposeKey`（后端 playbook 契约键，经 `lib/alertTriage.ts` 映射成 `alertTriage.purpose.<key>`）、
   `hostKey`/`authMethodPrivateKey`（SSH 领域概念）、以及恰好以 key 结尾的 `hotkey`。
   → 改用显式白名单 `labelKey`/`labelKeys` 并在注释里写明排除项及理由。

### 测量基线的手法（跨轮复用）

想知道「本分支到底新增了多少用例」，不要在分母上推算——**在 main 上起临时 worktree 实测**：

```bash
git worktree add --detach /tmp/ssh-main-probe main
ln -s <主检出的>/frontend/node_modules /tmp/ssh-main-probe/frontend/node_modules
(cd /tmp/ssh-main-probe/frontend && node node_modules/vitest/vitest.mjs run)
rm -f /tmp/ssh-main-probe/frontend/node_modules && git worktree remove --force /tmp/ssh-main-probe
```

要点：**先删符号链接再 `worktree remove`**（否则 `--force` 之外可能报非空），
且 vitest 走主检出的 `node_modules` 即可，无需重新装依赖。
实测结果：main = 64 文件 / 561 用例；本分支 = 70 / 680；净 +119
（= 新增 6 个 spec 共 126 例 − `terminalInteraction.spec.ts` 迁移走的 7 例）。
